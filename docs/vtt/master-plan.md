## Architecture decisions

1. **One scene across play modes.** Campaign owns named scenes; scenes own independently selectable floors, calibration, bounds and versioned vector layers. Combat references the existing scene and tokens. World coordinates use fixed units with elevation, floor reference, footprint and height. A floor is a surface/volume with ceiling and openings; stairs, ladders and pits connect endpoints. Multiple maps retain their positions when inactive. Encounters never own the only copy of a persistent actor, token or zone.
2. **One owner for each value.** Persistent HP/temp HP, inventory, slots, class features, conditions and owned creatures belong to the saved sheet or creature record. A token holds placement, representation and visibility; an encounter holds turn/order, budgets and pending resolutions. An encounter-local monster has its own resource state plus template ID, edition and content version. Each actor has a stable instance ID, campaign, lifecycle, controller grants and optional owner-sheet/creature reference. Model rider, mount, familiar perception, summoner, commander and effect links separately with start/end conditions. Delegation conveys specific commands, never the owner's full sheet.
3. **Renderer and geometry.** Begin with a local Canvas 2D viewport and accessible DOM controls/token list. It can overlay the current sheet without a second app or another WebGL context alongside the dice. Introduce a renderer adapter if measured redraw cost warrants WebGL. Store world coordinates independent of zoom, drawing layers, optional snapping and visible grid. Square and axial hex traversal use deterministic A* for a chosen path and bounded Dijkstra for reach. Gridless uses obstacle polygons, swept footprints and a visibility graph with terrain-weighted costs. Represent vertical extent and portals in all three modes. Define fixed precision, boundary contact, diagonal policy, ties and costs in edition/campaign profiles. Use matching golden geometry vectors in browser and trusted validation. Recompute legal segments/targets from private geometry on commit. Invalid previews return a generic blocked result when the cause is secret.
4. **Private projections first.** Canonical geometry, objects, DM notes, actors, prompts and sight sources live behind authenticated campaign RPCs. Enforce campaign membership and source/target control for every read/write; include campaign IDs in composite references. Fix definer search paths and grants. Campaign notifications contain only an invalidation revision safe for that audience; use a separate private channel/revision for DM-only changes if even an update would reveal activity. A per-viewer projection contains only authorized terrain, visible tokens, sensed uncertainty, owned resources and eligible prompts. The DM's perspective preview uses the same projection for the chosen player. Visible now, remembered floor geometry, detected presence and identified creature are distinct. Revoking membership invalidates subscriptions and clears caches, including pop-outs.
5. **Images and secrets.** Start with private Supabase Storage for campaign assets, scoped access, compressed raster formats and bounded upload sizes. Use a content hash within a campaign, references and orphan cleanup. A short-lived signed URL limits who can fetch a file, not which pixels they receive. Allow fully player-safe backdrops directly. Keep unsanitized masters DM-only; generate sanitized player tiles/crops server-side or explicitly approved safe derivatives. Withhold unknown regions entirely. Test downloads, caches, tiles, metadata, reconnect and permission revocation. Defer third-party providers until a measured deficit requires a decision.
6. **Commands and concurrency.** Common envelope: command UUID, ruleset/version, campaign, scene, encounter, actor, targets, expected revisions, kind, payload. Server derives principal, locks affected rows in consistent order, validates authority/rules and stores a durable receipt unique to campaign + principal + command. A replay returns the same filtered resolution; mismatched payload for the same key is rejected. Return accepted, pending or rejected with a stable reason and corrected projection. Persist sheet deltas, encounter state, resource spend, event and revision in one transaction per committed stage. Reconnect by last seen revision, fetching a snapshot on a gap. Retain dedup receipts through the retry horizon; reject older commands against closed encounters/obsolete revisions. A separate window is another view onto the same command state. Guard ordinary full-sheet autosaves against stale writes to server-managed fields.
7. **Resolution and dice.** Store an action intent with eligible targets, allowed dice, modifiers, visibility and spend boundary. Use existing settled dice and accessible/WebGL-off fallback; retries resume the same intent. For trusted-table mode accept a validated declared landing once and identify it as player-reported. For authoritative rolls generate faces on the server once, then reveal after synchronized presentation; use face-matched animation or an accessible fallback. Never claim client physics is independently verifiable. Finalize or cancel pending reactions per rules. Reserve resources until their rule-specific commitment; retain spent ammunition or a countered spell slot where appropriate. DM-confirmed physical dice and manual adjudication are explicit event types.
8. **Rules coverage and interruptions.** Campaign selects edition and per-mechanic manual, assisted, automatic or custom policy. Automatic requires a versioned rule ID and fixtures. Unknown homebrew presents a ruling with targets, costs and reason. Reaction windows persist stage, parent, eligible responders, priority and expiry policy; process one accepted response at a time and resume/revalidate parent. Default to DM-resolvable waiting on disconnect; a configured timeout may decline an optional prompt. Ready/held actions declare trigger and reserved resource. Keep off-turn reactions, legendary/lair actions and forced movement independent of ordinary turn authority. Undo on mutable game state creates an auditable compensating operation if subsequent actions depend on the original.
9. **Effects and time.** Link each application to source actor, cast/feature instance, affected actor/zone and timing rule. Anchor durations to the point of activation, with six seconds per full rotation; represent start/end of a named turn explicitly. Use game time in exploration and preserve remaining duration through encounters and rest. Handle concentration loss/replacement, voluntary end, incapacitation, death and feature-specific renewal. Remove only dependents of the ending instance. Store authoritative boundaries and meaningful events. Render countdowns locally. Use #64 as the compatibility bridge for existing sheet timers.

SQL sizes are point-in-time measurements; monthly egress, billed realtime deliveries/peaks and organization-wide consumption require the Usage dashboard. Other projects may share allowances. Consult [pricing](https://supabase.com/pricing), [billing scope](https://supabase.com/docs/guides/platform/billing-on-supabase) and [Realtime limits](https://supabase.com/docs/guides/realtime/limits) before release.

Target one campaign subscription per active browser context, an initial filtered snapshot, then coalesced changed objects. On the audited main branch, each visible watcher can issue 360 reads/hour. The foundation branch shares one filtered channel and one 10-second revision check per campaign per active service instance, with no revision polling while the tab is hidden. An idle visible campaign still costs up to 360 small requests/hour. Membership and owner-sheet reconciliation run separately. Measure total reads, bytes and reconnects with six real clients before rollout. Example test budget: 1 DM + 5 players, 4 hours, 600 committed operations. One 2 KiB delta per six recipients is about 7 MiB before protocol overhead, images and initial loads. Six independent 10-second pollers for this session would issue 8,640 reads even while idle. Require zero writes/traffic from local pointer movement, previews, dice frames or seconds ticking. Measure paid-meter categories separately. Start at 2 MiB per compressed map image, 20 MiB assets per campaign and a 250 KiB compressed initial vector projection per floor; benchmark these engineering targets on representative scenes. Alert operationally at 70% of shared monthly allowances and review budgets at 85%. No guaranteed unlimited host. Retain seven-day DM archives with local export; snapshot/compact drawing operations and retain short retry receipts; never record every frame or tile ray.

**Migration and rollback.** Use the isolated CLI/Postgres pipeline in shared-campaigns.yml, including existing schema, shared sheets, institute access, delete campaign, live campaign play, shared sheet edits, private initiative, encounter logs and then the turn clock. Each new migration is additive/versioned with explicit grants, indexes and backfill checks. Keep old clients and imports readable; rehearse retry after partial deployment. Enable new writes per campaign only after data/permission checks. Shadow-compare projections on fixtures; keep old UI and disable new routing on rollback. Snapshot affected game state before irreversible work; test compensating changes after new events exist. An older client must never roll back newer resource spends. Production migrations, merge, deployment, paid services and destructive actions require applicable explicit authorization.

**Release evidence.** Maintain a row per slice for commit, dependency version, commands/jobs, actual participants/scenario, request/byte counts and unresolved rules. At review #64 is the active P0 branch. P1–P10 are main-release commitments awaiting their gates. The map, player-specific visibility and creature relationships have no integrated release claim.
